# CANON — 発見が世界の正史になるAIサンドボックス

[English](README.en.md)

CANONは、素材を組み合わせた結果をAIが一度だけ裁定し、その発見を全プレイヤー共通の「正史」として保存するブラウザゲームのプロトタイプです。既に発見された組み合わせはデータベースから同じ結果を返すため、遊ぶほど共有世界のルールが増えていきます。

## 遊び方

1. ブロックを壊して素材を集めます。
2. `E` キーでクラフト画面を開き、2つの素材を選びます。
3. 未発見の組み合わせはAIが結果を作り、発見者名とともに正史へ保存します。
4. 発見済みの組み合わせはAIを呼ばず、同じ結果を再現します。
5. 右上のフィードで最近の世界初発見を確認できます。

## 現在の状態

最初のゲームループを確認するためのプロトタイプです。認証、複数サーバー間の同期、モデレーション、データ移行、運用画面は含まれていません。入力素材名と表示名は利用者が送信できるため、インターネットへ公開する前に追加の保護が必要です。

## ローカル起動

Node.js 22以上と、対象モデルを利用できるGemini APIキーが必要です。

```sh
git clone https://github.com/ZenLabInc/canon.git
cd canon
npm install
cp .env.example .env
# .envを開き、GEMINI_API_KEYを設定
npm start
```

ブラウザで <http://localhost:3000> を開きます。画像生成を試さず原価を抑える場合は、`.env` の `ENABLE_IMAGES=0` を使ってください。

APIキーをソース、スクリーンショット、ログへ貼らないでください。クラフト結果の新規生成と画像生成にはAPI料金がかかります。

## 設定

| 環境変数 | 既定値 | 内容 |
|---|---:|---|
| `GEMINI_API_KEY` | なし | Gemini APIキー。未発見のクラフトに必須 |
| `PORT` | `3000` | 待受ポート |
| `DB_PATH` | `./craft-cache.db` | 正史を保存するSQLiteファイル |
| `ENABLE_IMAGES` | `1` | `0`でアイコン画像生成を停止 |
| `MAX_NEW_PER_DAY` | `400` | 1日あたりの新規発見上限 |
| `RATE_PER_MIN` | `20` | IPごとの新規発見試行上限／分 |

これらは簡易的な原価保護です。複数プロセスではIP制限が共有されず、日次上限もSQLiteファイル単位です。

## APIとデータ

| 項目 | 内容 |
|---|---|
| `POST /api/craft` | 2素材と表示名を受け取り、既知結果または新規結果を返す |
| `GET /api/feed` | 最近の発見を最大15件返す |
| `combos` テーブル | 組み合わせキー、結果JSON、作成日時、発見者を保存 |

同じ2素材は入力順に関係なく同じキーになります。SQLiteを使うため、現在の構成は単一プロセスと永続ディスクを前提にしています。

## Docker

```sh
docker build -t canon .
docker run --rm -p 8080:8080 \
  --env-file .env \
  -v canon-data:/data \
  canon
```

<http://localhost:8080> を開きます。公開環境ではAPIキーをコンテナイメージへ含めず、ホスティング先のシークレット機能から環境変数として渡してください。

## 構成

- `server.js`：Express API、Gemini呼び出し、SQLiteへの保存
- `public/`：Three.jsを使ったゲーム画面
- `Dockerfile`：Node.jsコンテナ
- `scripts/start-local.sh`：`.env`を読み込むローカル起動補助
